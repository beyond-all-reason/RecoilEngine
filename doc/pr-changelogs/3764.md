 * add a new string springsetting, `SceneTarget`. Defaults to `direct` which is the existing behaviour. When set to `hdr` the world is drawn into a floating-point colour target and then shown through one display pass. If the target cannot be allocated, the engine falls back to `direct`.
 * add `DisplayBoundary` string springsetting. `after-world` (default) presents before the screen-space effects, so they still draw into the window; `after-screen-effects` presents after them, so they are tone mapped too
 * add `DisplayTransform` string springsetting: the tone curve the display pass applies with `SceneTarget = hdr`. Defaults to `khronos-neutral`; the others are `agx`, `aces`, `aces-hill`, `hable`, `uchimura`, `reinhard`, `reinhard-jodie`, `filmic-hejl`, `filmic-toe-shoulder`, `bar-custom`, `legacy` (no curve) and `linear-debug`.
 * add `DisplayExposureEV` float springsetting: scales the scene by 2^EV before the tone curve. Defaults to `0`.
 * add `DisplayDither` string springsetting. `triangular` (default) adds a 1/255 grain that hides banding in the 8-bit output; `off` leaves it out.
 * add `SceneDepthFormat` string springsetting for the scene target's depth. `d24s8` (default) copies depth and stencil into the window (depth only, by a shader, where the driver refuses the blit); with `d32fs8` depth is copied by a shader and stencil is not copied.
 * add `SceneColorFormat` string springsetting for the scene target's colour. `rgba16f` (default) or `r11g11b10f` (half the memory, no alpha).
 * add `SceneTargetForceFailure` bool springsetting, for testing only: makes the scene target allocation fail so the fallback to `direct` can be checked. Defaults to `false`.
 * add Lua function `gl.SceneTargetToneMapMask(enable)`. While enabled, every fragment shader that draws must write output location 1: `1.0` for scene-linear colour to tone map, `0.0` for colour that is already display-ready; the display pass applies the tone curve only to pixels marked `1.0`, so legacy-shaded pixels keep their look. Returns `false` and does nothing outside the HDR world phase.
 * add texture names `$scene_color` and `$scene_depth` for `gl.Texture` and material texture tables: the scene drawn so far during the world phase (colour sRGB-encoded and allowed above 1.0; depth with stencil). With MSAA they are resolved single-sample copies. They are 0 with `SceneTarget = direct`.
 * add texture name `$scene_tonemap_mask`: the resolved mask written through `gl.SceneTargetToneMapMask`. It is 0 with `SceneTarget = direct`.
 * add gadget call-in `DrawSceneDisplay(winSizeX, winSizeY)`: a game can draw the display pass itself from `$scene_color` and `$scene_tonemap_mask` and return `true`. The first handler that returns `true` wins; otherwise the engine's display pass runs.
 * add Lua function `Spring.GetSceneTargetInfo()`: whether the scene target is `direct` or `hdr` this frame, why it fell back, how depth is copied, and whether the engine or the game drew the display pass.
 * add Lua function `Spring.TestDisplayTransforms()`: runs a brightness ramp through every tone curve on the GPU and compares it with the CPU reference.
 * with `SceneTarget = hdr` and MSAA, `gl.CopyToTexture`, `gl.ReadPixels`, `gl.SaveImage` and `gl.BlitFBO(nil, ...)` resolve the scene before reading it.
