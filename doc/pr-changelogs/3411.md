Lua:
 - Lua garbage collection is now paced by allocation: each Lua state's collector runs work proportional to
   what that state allocated since its previous collection, instead of a random roll (by global memory load)
   followed by a fixed time budget. Idle states cost nothing, busy states are collected steadily, and the
   time budget now only caps the work of a single call, with the remainder carried over to the next frame.
 - At higher game speeds that per-call cap is still divided by the speed, but as the global Lua memory load
   rises from 25% to 50% of `LuaAllocLimit` the division is phased out, so fast playback under memory pressure
   cannot outrun the collector. The work requested per allocated kilobyte is unchanged.
 - `Spring.GarbageCollectCtrl` gained a ninth parameter `baseWorkMult`: kilobytes of collector stepping requested
   per kilobyte the state allocates. As before, `baseRunTimeMult` (seventh parameter) is the per-call time cap
   in milliseconds, which a game can raise at runtime for a state whose footprint keeps growing.
 - `Spring.GarbageCollectCtrl` is now also available to LuaMenu, so a lobby can lower its own collector budget
   while a game runs and restore it when it is back in front.

Misc:
 - New config `LuaGarbageCollectionWorkMult` (default 1.5): kilobytes of collector stepping per kilobyte a Lua
   state allocates; higher frees garbage sooner at more CPU cost, 1.0 lets memory drift upwards.
 - `LuaGarbageCollectionRunTimeMult` is now the cap on the time a single collection call may take per Lua
   state, no longer the time it always takes. `LuaGarbageCollectionMemLoadMult` now scales the requested
   collector work with the global memory load (its minimum is 0, previously 1) instead of the probability
   of collecting at all.
